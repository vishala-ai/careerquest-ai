## Reproduced defect and changes

After three quests, confirmation, and 31 reflections, `GET /summary` returned zero choices instead of three. Reposting the identical confirmation increased its version from 1 to 2 and awarded another 10 XP. Both operations incorrectly used the API's 30-event display window as their authoritative history.

- `careerquest/api.py`: summary and duplicate-confirmation checks now read complete stored event history. The timeline response remains limited to 30 events.
- `tests/test_api.py`: added `test_profile_history_survives_timeline_window`, covering retained quest evidence and unchanged version/XP on identical reconfirmation. Existing assertions and expected results were preserved.
- `frontend/package-lock.json`: generated by successful dependency installation.
- `docs/BASELINE_VERIFICATION.md`: this report.

Generated local artifacts: `.venv/`, `frontend/node_modules/`, `frontend/dist/`, and Python bytecode caches. Temporary download/cache files and the API verification helper are under `/private/tmp/`. No database migration or reset was performed. API verification used a disposable synthetic database; its two server processes were stopped.
